## 一、产品目标

### 1.1 现状问题

当前趋势页（trend-v2）本质是 **HTML 表格 + 圆点色块 + 简单连线**：
- 35×N 的表格格子承载"号码出现矩阵"，信息密度低、可读性差；
- 没有纵轴语义（行=号码，但缺少分组/分区可视结构）；
- 遗漏/热度只以底色阶表达，无量化对比；
- 无和值/跨度/区间等结构维度；
- 交互只有 hover tooltip，无筛选、切换、探索能力。

### 1.2 设计目标

把趋势模块从"开奖结果陈列"升级为**真正的数据分析可视化**：

| 目标 | 说明 |
| --- | --- |
| **可读** | 一眼看清号码出现轨迹、遗漏状态、热冷分布 |
| **可量化** | 每个状态都有数字：出现次数/当前遗漏/最大遗漏/平均遗漏/热度等级 |
| **可探索** | 用户可按期段、指标、前后区自由切换，hover 获得详情 |
| **有语义** | 连线表达数据关系（重号/斜连/趋势），而非装饰 |
| **可复用** | 号码规则参数化，后续双色球/3D/快乐8 直接复用 |

## 二、页面结构

```
┌──────────────────────────────────────────────────────────────┐
│ 顶部筛选区（固定）                                             │
│  [期段] 最近 10/30/50/100/300/1000 ｜ [分组] 前区 / 后区        │
│  [指标 tab] 轨迹 / 遗漏 / 热冷矩阵 / 和值跨度 / 奇偶大小        │
├──────────────────────────────────────────────────────────────┤
│ 主趋势图区（核心，SVG 画布）                                    │
│  ┌────────────────────────────────────────────────────────┐  │
│  │ 当前指标视图（按 tab 切换）                              │  │
│  └────────────────────────────────────────────────────────┘  │
├──────────────────────────────────────────────────────────────┤
│ 数据说明区（图例 + 口径 + 免责声明，常驻页脚上方）              │
├──────────────────────────────────────────────────────────────┤
│ 交互区（hover 详情浮层 / 图例开关 / 视图重置）                  │
└──────────────────────────────────────────────────────────────┘
```

### 2.1 顶部筛选区

- **期段**：10 / 30 / 50 / 100 / 300 / 1000（沿用现有 `PERIODS`，增加 10/30）；
- **分组**：前区（01-35）/ 后区（01-12）单选；
- **指标 tab**：轨迹 / 遗漏 / 热冷矩阵 / 和值跨度 / 奇偶大小——**所有视图共享同一期段与分组选择**，切换即时联动。

### 2.2 主趋势图区

单一 SVG 画布区域，按当前 tab 渲染不同视图（见三）。大屏展示 ≥300 期，移动端横向可滚。

### 2.3 数据说明区

图例（命中点/遗漏色阶/连线含义）、数据口径（"最近 N 期 × 前区 35 个号码"）、更新时间、免责声明（非预测）。

### 2.4 交互区

- hover 详情浮层（fixed 跟随，复用 G-1 的 `bindTrendTooltip` 模式）；
- 图例开关（重号连线/斜连连线/遗漏底色）；
- 视图重置按钮。

## 三、核心功能设计

### 3.1 号码出现轨迹图（主视图）

**坐标**：横轴 = 期号（时间），纵轴 = 号码（01-35 或 01-12，从上到下）。

**节点**：命中位置 = 圆点 + 号码文本（复用 G-1 的号码格内文本，改为 SVG `<circle>+<text>`）。

**连线语义**（关键：连线必须有数据意义）：
| 连线类型 | 语义 | 视觉 |
| --- | --- | --- |
| 重号连线 | 号码连续两期都出现（回看） | 实线（组色） |
| 斜连连线 | 相邻两期号码差 = 1（号码走势） | 虚线（弱化） |
| 遗漏回填 | 号码两次出现之间的遗漏期数 | 节点间底色/标注 |

**遗漏底色**：行背景按当前遗漏 miss-lv0-4 渐变色阶（保留现有语义，SVG `<rect>` 渲染）。

**期号轴**：刻度每 5/10 期显示期号后 3 位，hover 表头显示完整期号 + 日期（保留）。

### 3.2 遗漏趋势图

| 内容 | 实现 |
| --- | --- |
| 当前遗漏 | 每号一行横向条形（数值标注），TOP 遗漏排序 |
| 历史最大遗漏 | 与当前遗漏对比条（双条并列：当前/最大） |
| 平均遗漏 | 表格列（现有 `calculateMissing` 的 avg） |
| 遗漏变化 | 近 10 期遗漏曲线（可选，单号聚焦时展示） |

视图形态：**双条对比表 + 顶部遗漏排行**，替代现有单一遗漏表。

### 3.3 热冷分析矩阵

- **期段划分**：当前 N 期按每 10 期一段切片（如 100 期 → 10 段）；
- **矩阵**：横轴 = 期段，纵轴 = 号码，格值 = 该段出现次数，**热力图色阶**（0 灰 → 高频深色）；
- **冷热变化**：最近一段 vs 前一段出现次数差，↑/↓ 标注；
- **热度等级**：复用 `poolByTier`（热/中/冷三分位），图例显示。

### 3.4 和值 / 跨度趋势图（新增维度）

**数据源**：`dlt_history.json` 前端即时计算（新增纯函数 `calculateSumSpan`），输出：
```
{ front_sum: {p25,p75,mean}, front_span: {p25,p75}, back_span: {p25,p75} }
```
与后端 `analyze_sum_span` 契约一致。

**视图**：每期前区和值折线 + 历史 p25-p75 参考带 + 当前期标注点；跨度同理（两个 tab 或上下两图）。

### 3.5 奇偶 / 大小趋势（保留升级）

现有 `calculateOddEven` / `calculateBigSmall` 的比率条形升级为**每期比率折线 + 平均线**，展示结构演化而非单点占比。

### 3.6 hover 详情（统一浮层）

悬停任一命中节点，显示：
```
第 26093 期 · 2026-08-17
号码 22（前区） ｜ 热度 🔥
出现次数 52 ｜ 当前遗漏 3 期 ｜ 最大遗漏 14 期 ｜ 平均遗漏 6.2 期
该期开奖：前区 08 10 22 26 29 · 后区 03 10
```
数据全部来自前端已有计算（`calculateHot`/`calculateMissing`）+ 当期 issues。

## 四、技术方案

### 4.1 渲染技术选型

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 主图渲染 | **SVG** | 节点/连线/色块语义化、可交互、零依赖（符合项目"零框架"约束）、缩放清晰 |
| 热冷矩阵 | SVG `<rect>` 热力图 | 与主图统一 |
| 遗漏双条对比 | HTML/CSS | 表格信息密度更高，保留现有 `.stat-table` |
| 筛选/tab/图例 | HTML/CSS | 原生组件，无状态库 |
| 复杂折线（和值跨度） | SVG `<polyline>` + 参考带 `<rect>` | 同 SVG 体系 |

> 决策：**以 SVG 为核心统一渲染，HTML 表格仅用于统计列表**。不引入 ECharts 等库（体积/依赖约束 + 当前需求 SVG 完全可满足）。若未来需要 3D/复杂交互再评估。

### 4.2 数据来源

- **主数据**：`data/dlt_history.json`（前端 fetch，已有多期全量 1000 期）；
- **计算**：前端即时计算（`calculate*` 纯函数族，无新增请求）；
- **可选长历史**：`/api/issues?range=all`（D1，2900+ 期）作为 fallback/扩展——**本轮不启用，保留通道**。

### 4.3 是否需要新增 JSON

**不需要。** `dlt_history.json` 已包含全部原始数据（issue/date/front/back），所有指标均可前端计算。后端 `analyzer.py` 输出（freq/omit/oddEven/bigSmall/zone/sumSpan）作为口径参照与未来 D1 化依据，本轮不新增产物。

### 4.4 是否影响现有 workflow

**不影响。** 纯前端重构（trend-v2 三文件 + 可能新增 1 个独立 JS 模块），不触碰 workflow、Python、D1、数据文件。

### 4.5 新增/修改文件（实施时）

```
public/trend-v2.html   # 结构调整：筛选区 + tab + 图例 + 说明区
public/trend-v2.js     # 新增 calculateSumSpan / 视图渲染器（trajectory/missing/heatmap/sumspan）
public/trend-v2.css    # SVG 画布、节点、连线、热力图、浮层样式
public/trend-v2-views.js  # （可选拆分）各视图渲染模块，便于测试与复用
```
纯增量，现有 `renderTrajectoryHTML/drawTrendLines/bindTrendTooltip` 保留或演进。

### 4.6 性能预算

| 场景 | 规模 | 处理 |
| --- | --- | --- |
| 默认 100-300 期轨迹 | ≤300×35 ≈ 1.05 万节点 | SVG 直接渲染，无压力 |
| 1000 期轨迹 | 3.5 万节点 | 可承受；若卡顿则期号轴降采样 + 节点按需创建 |
| 热冷矩阵 | 期段×35 格 ≤ 千级 | 无压力 |
| 交互 | 事件委托（一个 listener） | 复用 G-1 `bindTrendTooltip` 模式 |

## 五、迁移方案

### 5.1 大乐透现有功能不受影响

- 重构仅改 trend-v2 三文件，**首页/选号/数据分析/我的方案 零改动**；
- 现有 URL `trend-v2.html` 与导航不变；
- 数据/工作流/部署链路不变；若上线后异常可快速回退旧版（保留旧实现为备选）。

### 5.2 平台化复用（对齐 Task 17.0 模板目标）

| 彩票 | 组模型 | 复用方式 |
| --- | --- | --- |
| 双色球 | 6+1 双组 | **同构**：组定义（count/min/max）参数化即复用全部视图 |
| 福彩 3D | 单组 3 位（positional） | 轨迹视图按"位"拆分（百/十/个），热冷/遗漏按位计算；SVG 渲染组件复用 |
| 快乐 8 | 20/80 单组大池 | 渲染组件复用；热冷矩阵期段划分复用；性能按 80 行评估 |

**复用边界**：本次重构将「数据计算」与「SVG 渲染」分离——
- `calculate*` 纯函数：接受 `issues + 组参数（min/max/count）`，与彩票品种无关；
- SVG 视图渲染器：接受统一数据契约（nodes/links/rows），由组参数驱动；
- 后续新增彩票只需提供 `lottery_xxx.yaml` 的组规则，视图自动适配（双色球同构、3D 按位、快乐 8 大池）。
