## 三、v1.2 候选方向（按优先级）

### P0 — 体验闭环必须（建议先行）

- **R1 动态报告列表**：`reports/` 下自动生成 `index.json`/索引页，首页「历史报告」板块改为读取列表渲染，彻底解决 D1 硬编码过期问题。
- **R2 自动部署真正生效**：在 README/DEPLOY 中明确「添加 `CLOUDFLARE_API_TOKEN` secret」的一键路径；可选提供本地校验脚本，确认 secret 配好后每日自动上线。
- **R3 数据源健壮性**：为 `scraper.py` 增加（a）请求头/重试/限流；（b）源站改版时降级到备用数据源（如中国体彩官网历史数据接口）；（c）抓取失败时在报告中明确标注「数据未更新」，而非静默旧数据。同步解决 D4/D5。

### P1 — 体验增强（价值明显，成本可控）

- **E1 最新一期号码球**：在「最新数据」板块用极少 JS 渲染最新一期红/蓝球（原 v1.1 方案 A 为守约而规避，v1.2 可放宽）。
- **E2 AI 走势解读**：基于现有 7 项统计指标（奇偶/大小/连号/冷热/区间/和值/跨度）模板化生成一段自然语言小结——**明确标注为统计描述，非预测**。
- **E3 历史验证系统**：对往期生成的推荐做「命中/偏差」回测统计，仅作娱乐偏差展示，强化「不保证中奖」的合规形象。
- **E4 数据可视化**：纯前端 SVG/Canvas 实现冷热号热力图、奇偶/大小分布饼图、前区走势折线，无图表库依赖。

### P2 — 扩展探索（按需、可独立成子版本）

- **X1 双色球支持**：将数据源/分析器抽象为可插拔后端，复用同一套报告与 Pages 展示。
- **X2 用户自定义策略**：Web UI 提供权重滑块，前端按权重调用既有推荐算法生成个性化组合（仍属娱乐）。
- **X3 多语言（i18n）**：中/英切换，便于开源国际化。
- **X4 PWA / 开奖提醒**：离线缓存 + 浏览器通知（注意合规与频率限制，避免骚扰）。
- **X5 SEO 深化**：`sitemap.xml` + JSON-LD 结构化数据，提升搜索引擎收录质量。

## 四、明确不做的范围

- ❌ 任何「预测中奖号码 / 提高中奖概率」的功能或表述。
- ❌ 付费、账号体系、后端 API 服务。
- ❌ 引入 React/Vue 等框架或 Vite/Webpack 等构建工具（保持纯 HTML/CSS/JS）。
- ❌ 新增需要密钥的外部服务依赖（部署仍仅 Cloudflare Pages + GitHub Actions）。

## 五、工程整理（v1.2 顺带完成）

1. `.gitignore` 补充 `charts/`、`.verify_tmp/`（解决 D6）。
2. 升级 GitHub Actions 版本以消除 Node.js 20 弃用警告（解决 D8）。
3. 优化 workflow 末步 `git pull --rebase` 容错（解决 D7）。
4. 为 `src/` 核心模块补单元测试（scraper/analyzer/recommender/validator），CI 增加 `test` 步骤。
5. 核查并修复数据期号陈旧问题（D4）。

## 六、验收标准（草案，落地时细化）

- [ ] 首页「历史报告」可列出最近 N 期且链接长期有效（D1 关闭）。
- [ ] 配置 `CLOUDFLARE_API_TOKEN` 后，一次 push 即可观测到 Pages 自动更新（D2/D3 关闭）。
- [ ] 源站异常时报告明确标注「数据未更新」，CI 不静默失败（D5 关闭）。
- [ ] 新增任一 P1 功能后首页/报告正常、移动端可读、无新增外部依赖。
- [ ] 工程整理 5 项全部完成，仓库无运行产物误提交。

## 七、排期原则（非承诺）

- 不预设硬性日期；建议 **P0 → P1 → P2** 顺序推进。
- 每个方向单独立项、独立验证、独立可回退，保持「优先稳定版本」底线。
- 任何涉及 workflow / 部署方式 / 算法核心的改动，沿用阶段 6 纪律：先规划、只读检查、分任务执行、完成暂停确认。
