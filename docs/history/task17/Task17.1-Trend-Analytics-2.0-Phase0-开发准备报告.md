## 一、当前问题分析

### 1.1 现状（G-1 第一阶段，已上线 commit `0eaa1e7`）

趋势页实现：
- **轨迹**：HTML `<table>` 号码×期号矩阵 + 命中格号码文本 + 遗漏色阶 + **SVG polyline 简单连线**（G-1 新增）；
- **统计**：热度排行表、遗漏表、奇偶/大小比率条；
- **交互**：hover tooltip（期号/日期/号码/遗漏/该期开奖）、时间范围切换（50/100/300/1000）。

### 1.2 核心问题（产品层）

1. **装饰性连线无分析价值**：`drawTrendLines` 用 polyline 连接「同一号码的各期命中点」，在 1000 期 × 35 号矩阵中形成杂乱折线，不表达热度/遗漏/连续性/趋势变化，反而增加视觉噪声；
2. **信息密度与语义不足**：格内只有号码，遗漏只靠底色阶，热冷无量化，缺少出现次数/当前遗漏/最大遗漏的并排对比；
3. **无结构维度**：缺少和值、跨度、区间、奇偶大小随时间的演化视图；
4. **交互单一**：只有 hover + 期段切换，无指标 tab、无图例开关、无分组切换。

## 二、废弃方案说明

### 2.1 废弃内容

**「开奖号码出现点 → SVG polyline 简单连线」方案整体废弃**：
- 删除 `drawTrendLines` 函数与其调用、API 导出；
- 移除 `renderTrajectoryHTML` 中的 `<svg class="trend-lines">` 包裹与 `.trend-wrap` 依赖；
- 移除 `trend-v2.css` 中 `.trend-lines` 样式（`.trend-wrap` 如无其他用途一并移除）。

### 2.2 废弃原因（记录在案）

1. 连线只连接「同一号码的命中点」，不编码任何分析含义；
2. 无法表达热度、遗漏、连续性、趋势变化；
3. 1000 期长矩阵下视觉噪声大于信息量；
4. 违反新设计原则——趋势图必须围绕「号码、时间、出现规律、遗漏变化、热冷变化、数据趋势」，而非装饰性连线。

### 2.3 保留资产（G-1 有价值部分不退回）

| 保留 | 说明 |
| --- | --- |
| 命中格号码文本 | 节点显示号码（矩阵格内） |
| 遗漏色阶 miss-lv0-4 | 行背景按当前遗漏分级 |
| 表头期号 title（完整期号+日期） | 时间轴语义 |
| hover tooltip（bindTrendTooltip） | 交互详情基础 |
| calculate* 纯函数族 | 数据层全部复用 |

## 三、新趋势模块架构

### 3.1 分层

```
┌────────────────────────────────────────────────────────┐
│ 交互层  init()：期段/分组/tab 联动、hover 委托、图例开关 │
├────────────────────────────────────────────────────────┤
│ 渲染层  renderTrajectory / renderMissing / renderHeatmap│
│         / renderSumSpan / renderRatio（组件化、组参数化）│
├────────────────────────────────────────────────────────┤
│ 数据层  calculateHot / calculateMissing / calculateSum  │
│         Span / calculateHeatMatrix / calculateOddEven   │
│         / calculateBigSmall（纯函数，前端即时计算）      │
├────────────────────────────────────────────────────────┤
│ 数据源  data/dlt_history.json（未来可选 D1 API 长历史） │
└────────────────────────────────────────────────────────┘
```

### 3.2 渲染技术决策（Phase 0.3）

| 视图 | 渲染 | 理由 |
| --- | --- | --- |
| 号码轨迹矩阵 | **HTML/CSS 增强表格** | 保留 sticky 表头/横向滚动/移动端；格内放号码+遗漏+热冷符号——**成熟走势图呈现方式，无连线** |
| 遗漏趋势 | HTML 表格（当前/最大双条 + 排行） | 信息密度高 |
| 热冷矩阵 | **SVG `<rect>` 热力图** | 期段×号码色阶，视觉直观 |
| 和值/跨度 | **SVG 折线 + 平均线 + p25-p75 参考带** | 这是「数据趋势折线」（和值随时间演化），**非号码出现点连线，符合新原则** |
| 奇偶/大小 | SVG 折线 + 平均参考线 | 结构演化 |

> **连线边界**：polyline 仅用于「和值/跨度/奇偶/大小」这类**聚合数据随时间变化的趋势线**；**禁止**用于「号码出现点」的装饰性连接。轨迹视图不出现任何跨点连线。

- **是否继续 SVG**：✅ 用于热力/趋势折线（小规模、零依赖、可交互）；
- **是否 Canvas**：❌ 当前数据量（≤3.5 万格）HTML/SVG 可承受；Canvas 增加命中检测复杂度。为快乐 8（80 号）预留评估阈值：单视图 >5 万节点再升级；
- **纯 HTML/CSS**：✅ 用于轨迹矩阵与统计表（混合方案）。

### 3.3 数据计算位置

- **前端即时计算**（默认）：纯函数从 `dlt_history.json` 计算，零请求、即时交互、不影响 workflow、静态站友好；
- **后端/D1 API**（未来扩展）：`/api/issues?range=all` 提供长历史，口径对齐 analyzer——本轮不启用，仅保留通道；
- **新增 JSON**：不需要。

### 3.4 多彩票扩展（规则参数化）


| 彩票 | 适配 |

## 四、页面设计（新）

```
┌ 顶部筛选区 ──────────────────────────────────────────────┐
│ 期段：10/30/50/100/300/1000 ｜ 分组：前区/后区 ｜ 重置      │
│ 指标 tab：轨迹 / 遗漏 / 热冷矩阵 / 和值跨度 / 奇偶大小     │
├ 主视图区（按 tab 切换）──────────────────────────────────┤
│  轨迹：号码×期号矩阵（命中格=号码+遗漏小字+热冷色+连号框）│
│  遗漏：当前/最大/平均 双条对比 + 遗漏排行                  │
│  热冷：期段×号码 热力图 + 冷热变化                        │
│  和值/跨度：折线 + 平均线 + p25-p75 参考带                │
│  奇偶/大小：比率折线 + 平均参考线                         │
├ 数据说明区（图例 / 口径 / 更新时间 / 免责声明）───────────┤
└ 交互：hover 浮层 / 图例开关 / 视图重置 ────────────────────┘
```

**轨迹格内信息设计**（核心，替代装饰连线）：
| 元素 | 表达 |
| --- | --- |
| 号码文本 | 该期出现 |
| 右上角小字 = 当前遗漏期数 | 遗漏量化 |
| 格底色 = 热冷分级（热/中/冷） | 热冷状态 |
| 加粗边框 = 重号（连续两期） | 连续性 |
| 行背景 = 当前遗漏色阶 miss-lv0-4 | 遗漏趋势 |
| hover 浮层 | 号码/期号/日期/出现次数/当前/最大/平均遗漏/热度 |

## 七、结论

- 旧「号码出现点 SVG 简单连线」**整体废弃并安全可移除**（独立函数，保留资产不受影响）；
- 新趋势模块以「号码×时间矩阵」为核心，量化表达遗漏/热冷/连续性，趋势折线仅用于聚合数据（和值/跨度/奇偶大小）；
- 技术选型：HTML 表格（矩阵）+ SVG（热力/趋势折线）混合，数据前端即时计算，零新增 JSON、零 workflow 影响；
- 架构对齐多彩票模板：数据层/渲染层/组参数化，可扩展双色球/3D/快乐 8；
- 开发按 S1-S7 分阶段推进，S1 先行清理旧连线。
